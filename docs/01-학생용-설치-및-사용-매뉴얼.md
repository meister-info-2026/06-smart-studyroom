## 💡 시작하기 전에: 1차 완성 상태 안내

이 저장소(`study` 브랜치)는 **1차 개발(Mock 백엔드, DB 스키마/시드, 실시간 대시보드, ONNX 기반 비전 클라이언트)이 이미 완성되어 작동하는 상태**입니다.

* **이미 완성되어 있으므로 하지 않아도 되는 작업**:
  * ❌ `npx create-next-app` 스캐폴딩 (대시보드 코드가 이미 완성되어 있습니다)
  * ❌ `AGENTS.md` 빈 양식 작성 (우리 팀의 AI 스마트 학습 좌석 기획이 채워져 있습니다)
  * ❌ 기초 백엔드/프론트엔드/비전 코드 처음부터 생성 (모두 구현되어 있습니다)
* **여러분이 진행할 2차 개발의 핵심 목표**:
  1. **저장소 클론 후 원스톱 환경 세팅 및 로컬 3개 터미널 즉시 구동/검증**
  2. **라즈베리파이 5 실제 하드웨어 핀 배선 및 `pi/main.py` 연동 (`Mock` ➔ `Hardware`)**
  3. **비전 인식 정밀도 개선 및 신규 센서/액추에이터 확장**
  4. **클라우드 배포 (FastAPI ➔ Render, Next.js ➔ Vercel, MySQL ➔ Supabase)**

## 0단계. 저장소 받기 (Clone) & Antigravity 설정

### 0-1. 저장소 클론 (study 브랜치)
PowerShell 터미널을 열고 아래 명령어로 저장소를 클론합니다:
```powershell
git clone -b study https://github.com/foxjini/agent-vibe-coding-starter-kit2.git agent-vibe-coding-starter-kit2-study
cd agent-vibe-coding-starter-kit2-study
```

### 0-2. Antigravity IDE로 열기
Antigravity IDE를 실행하고 방금 클론한 폴더(`agent-vibe-coding-starter-kit2-study`)를 워크스페이스로 엽니다.

### 0-3. Antigravity Rules 3개 "Always On" 확인
우측 상단 "…" 메뉴 ➔ **Customizations** ➔ **Rules** 패널에서 아래 3개 규칙만 **Always On**으로 켜져 있는지 확인합니다:
1. `karpathy-principles` (기본 설계 원칙)
2. `security-rules` (시크릿 보호)
3. `coding-standards` (코드 표준)

> 💡 나머지 규칙들은 각 에이전트 호출 시 자동으로 연동되므로 3개만 Always On으로 유지해야 토큰을 절약할 수 있습니다.

## 1단계. 원스톱 환경 세팅 & 패키지 설치

### 1-1. 환경변수(.env) 4개 복사 및 설정
각 폴더의 `.env.example`을 복사하여 `.env`를 만듭니다:
```powershell
copy backend\.env.example backend\.env
copy frontend\.env.example frontend\.env
copy vision\.env.example vision\.env
copy pi\.env.example pi\.env
```

> 🔐 **보안 주의 (`DEVICE_API_KEY` 동기화)**:
> `backend/.env`, `vision/.env`, `pi/.env`의 `DEVICE_API_KEY`는 서로 일치해야 인증을 통과합니다. 기본값(예: `smart-seat-secure-key-2026`)을 유지하거나 팀만의 고유 문자열로 3개 파일 모두 동일하게 맞춰주세요.

---

### 1-2. 백엔드 가상환경(venv) 및 패키지 설치
```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```
*(스크립트 실행 권한 오류 발생 시 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 실행)*

---

### 1-3. 프론트엔드 패키지 설치
⚠️ `create-next-app`은 절대 실행하지 않습니다. 이미 완성된 코드가 들어있으므로 `npm install`만 실행합니다:
```powershell
cd frontend
npm install
cd ..
```

---

### 1-4. 비전 클라이언트 패키지 설치 (초고속 경량 ONNX)
저장소에 공식 표준 초경량 모델 `vision/yolov8n.onnx`(12.8MB)가 이미 탑재되어 있습니다. 무거운 PyTorch 없이 `onnxruntime`과 `opencv-python`으로 10초 만에 설치가 완료됩니다:
```powershell
cd vision
python -m venv venv
.\venv\Scripts\Activate.ps1
$env:PYTHONUTF8=1
pip install -r requirements.txt
cd ..
```

---

### 1-5. 로컬 DB 초기화 (MariaDB / MySQL)
1. **XAMPP Control Panel**을 열고 Apache와 MySQL을 **Start**합니다.
2. 백엔드 폴더의 초기화 SQL을 실행하여 DB(`smart_seat_db`)와 테이블, 시드 데이터를 생성합니다:
```powershell
cd backend
Get-Content db\init.sql | mysql -u root
cd ..
```
*(mysql 명령어가 없을 경우 phpMyAdmin(`http://localhost/phpmyadmin`)의 SQL 탭에 `backend/db/init.sql` 내용을 복사하여 직접 실행해도 됩니다.)*

## 2단계. 1차 완성 시스템 로컬 구동 및 통합 검증

IoT 시스템은 백엔드, 프론트엔드, 비전 프로세스가 서로 실시간 통신합니다. **PowerShell 터미널을 3개 열어 동시 실행**합니다.

```
┌─────────────────────────┐     WebSocket (8000)    ┌─────────────────────────┐
│  터미널 1: 백엔드 (8000)  │ ◄──────────────────►  │ 터미널 2: 프론트엔드(3000) │
│  (FastAPI MockProvider) │                         │ (Next.js 실시간 대시보드) │
└─────────────────────────┘                         └─────────────────────────┘
             ▲
             │ POST /api/v1/vision/events
┌─────────────────────────┐
│  터미널 3: 비전 클라이언트 │
│  (ONNX 듀얼 추론/웹캠)   │
└─────────────────────────┘
```

### 2-1. [터미널 1] 백엔드 서버 실행
```powershell
cd backend
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```
* **확인**: 브라우저에서 `http://localhost:8000/docs` (Swagger UI) 및 `http://localhost:8000/health` 정상 응답 확인.

---

### 2-2. [터미널 2] 대시보드 프론트엔드 실행
새 터미널을 열고 프론트엔드를 구동합니다:
```powershell
cd frontend
npm run dev
```
* **확인**: 브라우저에서 `http://localhost:3000` 접속.
  * 상단에 **"● 실시간 연결됨" (녹색 배지)** 표시 확인.
  * 스탠드 조명 밝기 슬라이더, 진동 모터 수동 토글 버튼 동작 확인.

---

### 2-3. [터미널 3] 비전 클라이언트 실행 & 키보드 시뮬레이션
> ⚠️ **웹캠 충돌 방지**: Zoom, Teams, Discord, Windows 카메라 앱 등이 켜져 있다면 모두 종료하세요. 웹캠이 없어도 키보드 시뮬레이터로 100% 테스트 가능합니다!

새 터미널을 열고 비전 클라이언트를 실행합니다:
```powershell
cd vision
.\venv\Scripts\Activate.ps1
python main.py
```

* **동작 검증 (웹캠 HUD 화면이 활성화된 상태에서 키보드 입력)**:
  * **숫자 `1` 키**: 착석(Seated) 토글 ➔ 대시보드의 학습 타이머가 자동으로 시작되고 조명이 켜짐
  * **숫자 `2` 키**: 졸음(Drowsy) 토글 ➔ 대시보드에 빨간색 졸음 경보 팝업 펄스 발생, 방석 진동 모터 가동
  * **숫자 `3` 키**: 거북목/숙임(Turtle Neck) 토글 ➔ 대시보드에 노란색 자세 불량 경보 팝업, 등받이 진동 모터 가동
  * **숫자 `0` 키**: 정상 상태로 리셋
  * **대시보드 "퇴실 및 학습 완료" 버튼 클릭**: 세션 리포트 및 스마트폰 스캔용 QR 코드 모달 확인

## 3단계 (2차 개발 1). 라즈베리파이 5 실제 하드웨어 연동

1차 검증(Mock)이 완료되었으므로, 실제 라즈베리파이 5 기기에 하드웨어를 연결하고 연동합니다.

> 📖 **필수 참고 문서**:
> - [부록A. 백엔드↔라즈베리파이5 연동 인터페이스 가이드](부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md) (REST 폴링 규격)
> - [부록B. 라즈베리파이5 담당자 온보딩 슬라이드](부록B-라즈베리파이5-담당자-온보딩-슬라이드.pptx) (GPIO 핀 배선 안내)

### 3-1. Windows PC의 로컬 IP 확인
PowerShell에서 IPv4 주소를 확인합니다:
```powershell
ipconfig
# IPv4 주소 확인 (예: 192.168.0.25)
```
라즈베리파이의 `pi/.env` 파일에서 `BACKEND_URL`을 설정합니다:
```ini
BACKEND_URL=http://192.168.0.25:8000
DEVICE_API_KEY=smart-seat-secure-key-2026
POLLING_INTERVAL=1.0
```

### 3-2. 라즈베리파이 5 패키지 설치 & 실행
라즈베리파이 터미널에서:
```bash
cd pi
python3 -m venv venv
source venv/bin/activate
pip install gpiozero lgpio requests python-dotenv
python main.py
```

### 3-3. 백엔드 모드를 하드웨어로 전환
`backend/.env` 파일에서 디바이스 모드를 변경하고 백엔드를 재시작합니다:
```ini
DEVICE_MODE=hardware
```
* **확인**: 웹 대시보드에서 버튼을 조작하거나 비전 AI에서 졸음/자세 불량이 발생했을 때 라즈베리파이에 연결된 실제 진동 모터 및 조명이 동작하는지 확인합니다.

## 💡 트러블슈팅 (자주 묻는 질문)

| 증상 | 원인 및 해결 방법 |
|---|---|
| `ModuleNotFoundError: No module named 'backend'` | `backend/` 폴더 안으로 이동(`cd backend`)한 뒤 `uvicorn main:app`을 실행하세요. |
| 대시보드 배지가 "● 연결 대기 중"으로 뜸 | 백엔드 서버(터미널 1, 포트 8000)가 정상 실행 중인지 확인하세요. |
| 비전 실행 시 웹캠 화면이 안 뜨거나 에러 | 다른 화상 프로그램(Zoom, Teams 등)을 완전히 종료하세요. 웹캠이 없어도 키보드 `1`, `2`, `3` 키로 완벽히 시뮬레이션할 수 있습니다. |
| 라즈베리파이에서 백엔드 연결 거부 (`Connection Refused`) | Windows PC의 방화벽에서 8000번 포트를 허용해야 합니다. (관리자 권한 PowerShell: `netsh advfirewall firewall add rule name="fastapi-dev" dir=in action=allow protocol=TCP localport=8000`) |
| `401 Unauthorized` 에러 | `backend/.env`, `vision/.env`, `pi/.env`의 `DEVICE_API_KEY`가 동일한지 확인하세요. |
| DB 연결 실패 (`Access denied` / `Unknown database`) | XAMPP MariaDB가 켜져 있는지 확인하고, `backend/db/init.sql`을 실행해 `smart_seat_db`를 생성했는지 확인하세요. |
