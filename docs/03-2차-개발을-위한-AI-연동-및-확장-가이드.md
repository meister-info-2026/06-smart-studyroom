# 03. 2차 개발을 위한 AI 핸드오프 및 시스템 확장 가이드

> **대상**: AI 스마트 학습 좌석 프로젝트를 이어받아 2차 개발(기능 추가, 파라미터 튜닝, 라즈베리파이 5 실제 하드웨어 연결, 클라우드 배포)을 진행하는 학생 및 생성형 AI
> **활용 방법**: 새로운 채팅창이나 세션에서 생성형 AI에게 작업을 요청할 때, **이 문서 전체 또는 해당 섹션을 프롬프트의 컨텍스트로 제공**하면 AI가 현재 아키텍처를 정확히 이해하고 기존 코드를 망가뜨리지 않고 안전하게 확장 작업을 수행합니다.

## 1. 프로젝트 개요 및 1차 완성 현황

- **프로젝트명**: AI 스마트 학습 좌석 (On-Device Vision AI 기반 학습 케어 및 자세 교정 플랫폼)
- **1차 완성 상태**: 라즈베리파이 5 대신 **Windows PC 환경에서 100% 자립 동작하는 Mockup 기반 완성본**
  - **백엔드 (FastAPI)**: 디바이스 상태 관리(`MockDeviceProvider`), 비전 AI 트리거 비즈니스 로직(`trigger_service.py`), REST API, WebSocket 실시간 브로드캐스트, MySQL(MariaDB) 스키마 및 시드 데이터 적재 완료
  - **비전 클라이언트 (Windows PC)**: YOLOv8n 기반 착석, 머리 Y축 하강(거북목/숙임), 눈 깜빡임(졸음) 감지 및 백엔드 전송 + 키보드 가상 시뮬레이션 인터랙티브 모드 완비
  - **대시보드 (Next.js)**: 실시간 WebSocket 연결 배지, 착석 연동 누적 공부 시간 타이머, 조명 밝기 조절 슬라이더, 졸음/자세 경보 카드(수동 해제 지원), 디바이스 카드 그리드, 퇴실 및 스마트폰 스캔용 QR 코드 모달 완비
- **2차 개발 목표**:
  1. 실제 라즈베리파이 5 + GPIO 핀 배선 및 하드웨어 연동 (`Mock` → `Hardware`)
  2. 비전 인식 정밀도 개선 및 추가 센서/액추에이터 확장
  3. 클라우드 배포 (FastAPI → Render, Next.js → Vercel, MySQL → Supabase)

## 3. 동작 테스트 및 검증 절차

3개의 PowerShell 터미널을 실행하여 시스템을 검증합니다:

```powershell
# [터미널 1] 백엔드
cd backend
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000

# [터미널 2] 프론트엔드
cd frontend
npm run dev
# 브라우저: http://localhost:3000 접속 ("● 실시간 연결됨" 확인)

# [터미널 3] 비전 클라이언트
cd vision
.\venv\Scripts\Activate.ps1
python main.py
```

### 테스트 단축키 (비전 창 활성화 시)
- **`[Space]`**: 착석 / 미착석 토글 → 대시보드 타이머 시작/정지, 조명/스크린 자동 On/Off
- **`[D]`**: 졸음 감지 발생 → 방석 진동 모터 B 작동, 조명 점멸, 3초 후 자동 해제 (수동 해제 가능)
- **`[P]`**: 자세 불량(거북목) 발생 → 등받이 진동 모터 A 작동, 2.5초 후 자동 해제
- **`[퇴실 & 리포트 발행]` (대시보드 버튼)**: 누적 시간 및 집중도 점수 요약 모달 및 스마트폰 스캔용 QR 코드 출력

## 4. 핵심 API 및 통신 규격

### 4.1. 인증 원칙 (반드시 분리)
- **사용자향 (대시보드)**: 브라우저 세션 / 추후 Supabase JWT
- **디바이스향 (라즈베리파이, 비전 클라이언트)**: HTTP Header `X-Device-Api-Key: STUDY_ROOM_2026_09_05_v1_0_0`

### 4.2. 주요 REST 엔드포인트

| Method | Endpoint | 설명 | 인증 |
|---|---|---|---|
| `GET` | `/health` | 서버 헬스체크 (`{"status": "ok", "mode": "mock"}`) | 없음 |
| `GET` | `/api/devices` | 전체 디바이스 목록 및 최신 상태 조회 | 없음 |
| `POST` | `/api/devices/{id}/control` | 디바이스 수동 제어 (`{"desired_state": "on", "value": {"brightness": 80}}`) | 대시보드 |
| `GET` | `/api/v1/devices/{id}/desired-state` | **(라즈베리파이용)** 목표 상태 폴링 | `X-Device-Api-Key` |
| `POST` | `/api/v1/devices/{id}/state` | **(라즈베리파이용)** 실제 하드웨어 반영 상태 보고 | `X-Device-Api-Key` |
| `POST` | `/api/v1/vision/events` | **(비전용)** 감지 이벤트 전송 (`{"event_type": "drowsiness", "detected": true}`) | `X-Device-Api-Key` |
| `POST` | `/api/v1/seat/telemetry` | **(비전용)** 종합 텔레메트리 전송 (`SEAT_TELEMETRY`) | `X-Device-Api-Key` |
| `POST` | `/api/session/checkout` | 퇴실 처리 및 요약 통계(공부 시간, 집중도 점수, QR 페이로드) 반환 | 대시보드 |

### 4.3. WebSocket 메시지 규격 (`ws://localhost:8000/ws`)
백엔드 상태 변경 시 모든 클라이언트에 아래 JSON 메시지가 브로드캐스트됩니다:

```json
  ]
}
```

## 5. 수정 및 보완 가이드 (파라미터 튜닝)

### 5.1. 비전 감지 임계값 조정 (`vision/main.py`)
- **거북목/고개숙임 감지 민감도**:
  - `head_y - self.base_head_y > 45`: 숫자가 작을수록 더 작은 숙임에도 민감하게 반응합니다.
- **졸음 판정 기준 시간**:
  - `now - self.eyes_closed_start_time >= 2.5`: 기본 2.5초. 필요에 따라 2.0초 또는 3.0초로 변경합니다.

### 5.2. 백엔드 자동 제어 시간 조정 (`backend/services/trigger_service.py`)
- **미착석 절전 전환 시간**:
  - `unoccupied_duration >= 30.0`: 기본 30초. (데모 시 15초로 단축 가능)
- **진동 모터 자동 정지 시간**:
  - `_auto_turn_off_vibrator("vibration_motor_b", 3.0)`: 졸음 방석 진동 지속 시간 (기본 3.0초)
  - `_auto_turn_off_vibrator("vibration_motor_a", 2.5)`: 자세 교정 등받이 진동 지속 시간 (기본 2.5초)

## 6. 기능 추가 방법 (신규 디바이스 추가 4단계)

새로운 센서(예: 조도 센서)나 액추에이터(예: 부저, 팬)를 추가할 때는 다음 4단계를 순서대로 진행합니다:

1. **DB 시드 등록**:
   - `backend/db/init.sql`의 `INSERT INTO devices`에 새 디바이스(`id`, `name`, `kind`) 행 추가.
2. **백엔드 Provider 상태 지원**:
   - `backend/iot/mock_provider.py`에서 새 디바이스 kind에 대응하는 초기값 설정.
3. **트리거 규칙 추가 (필요 시)**:
   - `backend/services/trigger_service.py`에 새 디바이스를 켜고 끄는 로직 추가.
4. **대시보드 UI 연동**:
   - `frontend/types/dashboard.ts` 확인 및 `frontend/app/page.tsx`의 액추에이터/센서 분류에 추가하여 화면에 자동 렌더링.

## 7. 라즈베리파이 5 마이그레이션 가이드 (2차 완성: Hardware Swap)

라즈베리파이 5 실제 기기로 전환할 때의 핵심 지침입니다:

### 7.1. 하드웨어 배선 및 GPIO 핀 맵 (권장)
> ⚠️ **라즈베리파이 5 주의사항**: Pi 5는 RP1 칩셋을 사용하므로 `lgpio` 라이브러리가 필수입니다.

| 디바이스 ID | 실제 부품 | GPIO 핀 번호 (BCM) | 제어 방식 (gpiozero) |
|---|---|---|---|
| `rgb_led` | RGB LED 바 / 스탠드 조명 | GPIO 18 (PWM) | `PWMLED(18)` 또는 `LED(18)` |
| `vibration_motor_a` | 등받이 진동 모터 | GPIO 23 (MOSFET) | `OutputDevice(23)` |
| `vibration_motor_b` | 방석 진동 모터 | GPIO 24 (MOSFET) | `OutputDevice(24)` |
| `relay_power` | 릴레이 모듈 (주전원) | GPIO 25 | `OutputDevice(25)` |

### 7.2. 생성해야 할 2개의 하드웨어 파일

#### ① 백엔드 쪽: `backend/iot/hardware_provider.py`
- **역할**: 백엔드는 GPIO를 직접 만지지 않는다. DB에 `desired_state`를 기록하고, 라즈베리파이가 폴링해 갈 수 있도록 중계하는 역할만 수행합니다.
- `base.py`의 `DeviceProvider`를 상속받아 구현합니다.

#### ② 라즈베리파이 쪽: `pi/main.py`
- **역할**: 백엔드를 1~2초 간격으로 폴링(`GET /api/v1/devices/{id}/desired-state`)하여 실제 GPIO를 켜고 끄고, 결과를 백엔드에 보고(`POST /api/v1/devices/{id}/state`)합니다.
- `pi/` 폴더는 독립적인 라즈베리파이 환경이므로 `backend` 코드를 import하지 않고 순수 `requests` + `gpiozero`로만 구성합니다.

### 7.3. 모드 전환
라즈베리파이 데몬이 준비되면 `backend/.env` 파일에서 한 줄만 수정하고 백엔드를 재시작합니다:
```properties
DEVICE_MODE=hardware
```

## 8. 생성형 AI에게 전달할 복사/붙여넣기용 프롬프트 템플릿

### 템플릿 A: 라즈베리파이 5 하드웨어 연동 요청 시

```markdown
2. pi/main.py를 작성해줘. docs/부록C-백엔드-라즈베리파이5-연동-인터페이스-가이드.md의 3장 REST 규격에 따라 백엔드를 1초 주기로 폴링하여 gpiozero(lgpio 팩토리)로 실제 GPIO(LED 바, 등받이 진동 모터, 방석 진동 모터, 릴레이)를 제어하고 결과를 보고하는 독립 데몬으로 만들어줘.
```

### 템플릿 D: 비전 AI 고도화 및 얼굴인식/인증 확장 요청 시
```markdown
너는 이 프로젝트의 vision-agent다. .agents/skills/vision-recognition-integration/SKILL.md를 따른다.

[주의 및 필수 준수 규칙]
1. Windows C++ 컴파일 에러를 유발하는 dlib / face_recognition 라이브러리는 절대 사용/설치하지 않는다.
2. 얼굴인식/학습자 인증이 필요한 경우, LFW 99.5%+ 정확도의 onnxruntime(경량 ArcFace ONNX) 또는 OpenCV DNN(YuNet+SFace)을 사용한다.
3. 웹캠 HUD 화면에 학생 이름 등 한글 텍스트 출력 시 cv2.putText()의 깨짐(? 표시)을 방지하기 위해 반드시 Pillow(PIL) ImageDraw를 활용한다.
4. 가상환경은 Python 3.14 DLL 충돌 방지와 .gitignore 호환을 위해 반드시 `py -3.12 -m venv venv`로 통일한다.

[구현 요청 사항]
기존 vision/main.py의 착석/졸음/자세 감지 파이프라인을 유지하면서, 위 규칙에 맞추어 [예: 학습자 얼굴 등록 및 인식 로그인 / 한글 HUD 오버레이] 기능을 추가해줘.
```
